# 项目、设备与任务集成说明

## 数据与接口

浏览器 → Fire 平台 → `airport_service` → portal → Open-RMF / ROS 2 / Gazebo。相机、导出和场景操作由 `/airport-runtime/*` 同源代理传输。

`sample_data/resources.json` 是初始台账。平台和场景构建共同读取，通过 platform_id 将稳定运行模型名对应到 PERSON/ROBOT/DOG/DRONE-01…07。编辑名称写入资源覆盖配置，运行 ID 不变。位置只取遥测，人员不产生虚构定位。

默认机场项目 `airport-t1`，电网项目 `dispatch-pool`。切换后设备来源、任务、反馈、地图和调度入口一起切换。未配置运行服务的项目只显示档案状态；机场任务运行中禁止切换。

| 接口 | 功能 |
| --- | --- |
| GET /api/projects | 项目列表与 active 项目 |
| POST /api/projects | `{name,kind,location}` 新建，或 `{active:id}` 切换 |
| POST /api/resources | 按既有 id 更新 name/vendor/protocol/access |
| GET /api/overview | 当前项目资源与概要 |
| GET/POST /api/tasks | 工单；机场 station=airport-t1、type=joint |
| POST /api/airport/start | `{task_id}` 启动工单；空对象创建并启动七区工单 |
| GET /api/airport/status | 统一 ID/名称后的场景、设备与任务状态 |
| GET /api/feedback | 当前项目证据与人工反馈 |
| POST /airport-runtime/api/physics | 暂停/继续 |
| POST /airport-runtime/api/obstacle | 围挡生成/移除；LaserScan 触发封路 |
| GET /airport-runtime/api/report | 当前工单导出 |
| GET /airport-runtime/api/trace | 位姿与路径导出 |

工单 requirements.cells 为 A–G 无重复数组，空数组代表全部。运行服务返回 mission_id，平台保存 task_id ↔ mission_id。拒绝启动不会标为执行中。计划时间暂不触发定时派单。

完成依据是实际 RMF 子任务状态、到点位置、连续驻留。每区保存初检、空中复核、交接三张证据。相机仅有全景、首台机器狗、首架无人机三个通道，其他区域使用全景证据。

任务快照在查询时同步并保存，断连保留最后进度；运行服务重启或任务 ID 更换后，未完成旧工单标为异常。任务异常不代表实体硬件急停，尚未接入硬件安全控制。

## 场景扩展

fleet_config.py 集中定义七区、资源、工位、相机和路网；build_scene.py 生成 world、车队和导航配置。扩容需同步增加台账、模型/驱动、停靠点并验证，不能只增加界面数字。

二维地图直接读取 scene.points/edges，位置来自 devices.pose。萧山区域地图未与当前室内模型配准。用户提供平面图/点云/BIM 后，需要建模、标定尺度和坐标、生成通行图和碰撞模型，再验证任务；卫星图无法单独提供可靠室内结构。
