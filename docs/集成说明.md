# 合并说明与代码索引

## 数据链路

浏览器 → Fire 平台 `8001` → `/airport-runtime/*` HTTP 代理 → 机场 portal → ROS 2 / Open-RMF / Gazebo。

页面为 `/airport-console`，保留 Fire 导航和标题栏，内嵌 `/airport-console/view/`。iframe 与宿主页同源；源代码仅有一份，来自 `simulations/airport-upgrade/site/`，不再复制两套控制台文件。两种服务保持独立进程，避免改变已有任务执行逻辑。

默认本机方式复用已有的 `8094` 服务。独立方式使用 Compose 的 `airport` 服务、ROS_DOMAIN_ID=45；原实例使用 44，避免车队消息相互干扰。平台数据、机场证据、报告与事件分别用 Docker 卷保存。

## 本轮边界

本轮只合并平台入口与现有实时控制台，不修改机场协作编排、路径规划、设备数量或场景内容。平台总览中的电网台账与机场台账仍是两套运行数据。要进一步统一任务创建、设备管理和调度，需要定义设备 ID、任务状态与告警映射，再建设业务适配层。

原 `web/airport-ops/` 为录像及记录回放页面；新增实时页面为 `/airport-console`，二者用途不同。旧版 `simulations/airport/` 快照不进入公开首发，当前集成使用 `simulations/airport-upgrade/`。

## 部署注意

网关只支持当前控制台需要的 HTTP 与 MJPEG，未接入 noVNC 的 WebSocket 桌面功能。完整实时演示需要持续运行机场后端，不能把 HTML 上传到 GitHub Pages 就替代 Gazebo。若另配公网入口，必须由部署者增加身份验证和 HTTPS，并设置流式响应不缓冲。

本项目发布到公开仓库：<https://github.com/xueReact/hetero-ops-platform>。登录名为 `xueReact`；个人资料显示名可以设置为 `ZYYYY`，不会改变仓库 URL。当前发布分支为 `main`。
